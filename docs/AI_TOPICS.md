# 本地 AI 话题搜索

用户从同一个搜索面板找到以前的 Claude Code、Codex 或 WorkBuddy 对话，确认命中片段后打开对应应用。包含 Claude 桌面 Code 会话，不包含普通 Claude 网页聊天或尚未落到本机的远端正文。

## 界面与动作

在原分类栏末尾增加「AI 话题」tab。「全部」同时搜索文件与话题，文件分类只显示文件，AI 话题分类只显示话题；删除独立的文件/话题范围切换和单独的来源筛选。输入框、结果列表、50 点行高、选择态、滚动、排序和面板动效均复用宿主。结果使用真实应用图标、实际标题、命中片段、应用/项目和日期，来源图标出处记录在 Resources/TopicIcons/README.txt。

上下键、Home/End、Page Up/Down、Tab 切分类和原分类快捷键沿用宿主；Return 打开，Claude / Codex / WorkBuddy 的 ⌘C 复制继续会话命令，⌥⌘C 复制标题。直接返回完整匹配结果，虚拟表格按需渲染，不提供「显示更多」。异步查询按统一代次取消旧请求；文件名称先就绪可先显示，话题合并后保留选中身份与滚动位置；话题分类等待时保留旧结果并显示搜索忙碌。话题不提供文件的预览、访达显示、拖拽或删除动作。右键菜单捕获原话题身份，执行前再次按 key 验证未删除、未归档且功能可用。

Codex 使用 codex://threads/UUID。Claude 桌面 local_ 会话使用已安装应用的 claude://claude.ai/epitaxy/local_ID 路由；CLI 会话通过临时自删除 .command 在 Terminal 执行 shell 转义后的 resume 命令，不发送新提示词。只有桌面 ID 的会话复制 open 深链命令。无法打开时保留结果并显示错误。菜单不提供删除原始会话。

## 索引与同步

功能随开源免费版提供，源码、图标、设置及测试均在公开仓库；不依赖授权、试用或私有模块。AppDelegate 持有单个 AITopicManager，搜索与设置复用同一实例，AdditionalSearchProvider 将话题并入原结果列表。设置开关控制索引与搜索。首次启用在后台建索引，先导入标题，再解析历史正文；已有索引直接可读。主文件索引繁忙且搜索面板未打开时让出后台资源。关闭开关或退出应用时取消任务；关闭开关会撤下分类及话题结果，已有索引保留。

设置中可分别开启 Claude Code（含桌面 Code 会话）、Codex 与 WorkBuddy，未配置过的来源按本机安装情况决定默认开关；用户手动选择独立持久化。关闭单个来源后立即撤下其搜索结果、数量和旧菜单动作，停止读取及监听该来源；保留缓存，重新开启时增量同步。所有来源均关闭时不展示话题分类。切换来源会使进行中的旧查询与导入代次失效；对账删除只作用于本次启用的来源，避免清除禁用来源的缓存。

独立 SQLite WAL 索引保存在 ~/Library/Application Support/Oil Find/ai-topics/index.sqlite，沿用原路径以复用已有索引；目录权限 0700、文件权限 0600。串行写入和独立串行读取连接，正文缓存有 32 MiB 上限。FTS5 gram postings 产生话题候选，再做规范化 UTF-8 字面验证；消息用 ZLIB、验证文档用 LZFSE 压缩。新增正文按变更消息分块维护，替换和删除通过有效消息归属排除旧内容，已有索引原地兼容。重复查询可复用有容量上限的完整结果缓存，写入或外部数据库变化后失效。只保留一份数据库，首次完整导入后合并 FTS 并压实，正常刷新做 WAL checkpoint。

历史正文导入按工作线程的实际 CPU 时间主动限速，目标为单个核心的 25%。每次最多休息 10 ms，等待期间继续检查取消；元数据先于历史正文同步，搜索使用独立读取队列。单次系统 JSON 解析、压缩或首次压实仍可能短暂突发，因此预算控制持续占用，并非每个采样瞬间的硬上限。限速会延长首次补齐历史正文的总耗时。

读取 CODEX_HOME / CLAUDE_CONFIG_DIR / WORKBUDDY_CONFIG_DIR 或默认目录。Codex 动态选择最高版本 state_*.sqlite、thread_history_*.sqlite，优先实际显示名 name，排除子代理；旧版支持 JSONL。权威 history 已覆盖的已知日志在打开前跳过；其他日志按文件身份复用首行识别结果，新增或重写文件才重新读取头部。目录日志排序只读取每个路径的修改时间一次；每次仍读取最新 Codex 元数据，来源数据库身份和行内容相同、显示信息完整时复用已同步行，避免重复读取索引正文。Claude 合并桌面描述符与顶层项目 JSONL，按 cliSessionId 去重。仅保存用户与助手文本，忽略工具和思考正文。

FSEvents 监听来源目录，0.15 秒延迟、0.25 秒合并后增量同步；新来源目录由父目录监听发现。唤起面板立即补查，另每 30 秒兜底检查。普通来源事件按 Agent 合并入队，不取消其他来源已经完成的工作。调度先更新待处理来源的标题和归档元数据，再轮流补全正文；Claude 与 Codex 的正文计划可在话题事务之间让出并续跑，避免持续写入把后面的来源饿死。关闭、退出与生命周期变化仍会取消，单话题事务保证取消时不留下半条正文。Codex 的版本化 state/history 数据库及其 WAL 额外使用 vnode 通知，避免仅依靠持续打开 WAL 的 FSEvents 合并事件；目录变化时更新监听路径。来源枚举不完整时保留缓存，完整枚举后对账删除。

处理重复刷新、重新打开、未写完 JSON、追加、重写、清空、删除和归档迁移。搜索仅返回未归档话题：全部来源、单一来源、标题、正文和空查询均在分页前排除归档项；设置中的话题数量也只统计未归档项。归档状态随来源同步，取消归档后复用保留的正文索引恢复搜索；执行旧结果的动作前再次解析并拒绝已归档项。空桌面标题继承已从正文解析的信息；Codex history 的 live message keys 对账撤下删除正文，已成为权威来源的 history 清空后不从遗留 JSONL 恢复。删除路径先解析最近存在的父目录，以兼容 /private 路径别名。

## WorkBuddy

以 WorkBuddy 5.6.2 的本地保存格式为依据：只读 `.workbuddy/workbuddy.db` 的 `sessions`，只收录 `transport=local`、`deleted_at IS NULL`、属于当前账号或旧版空账号的行。`custom_title` 优先于 `title`；`status=archived` 独立控制归档。数据库为会话身份和可见性的权威来源，不从孤立日志恢复已删除话题。保留 assistant/claw 的本地会话类别，不把界面分组误认为删除状态。

账号范围来自 `storage/skeleton/account-snapshot.json` 的非敏感 UI 缓存：校验 4 KiB 上限、version=1、uid/nickname/type 与有限 savedAt，沿用来源的 30 天有效期。不读取加密认证文件，不猜测数据库中的账号。缺失、损坏、过期或切换账号时撤下原账号索引；独立 `topic_scopes` 记录在读取来源数据库前切换范围，即使新账号数据库暂时不可读也不会保留旧账号正文。该缓存不证明在线登录状态，文件未能删除时仍存在来源缓存自身的限制。

正文来自 `projects/<key>/<id>.jsonl` 顶层日志，排除嵌套子代理、`session_settings.conversationTags.wbQuickAsk="1"` 和 `.quickask` 临时标记。兼容同目录 `.acp-session.json` 到另一 ACP ID 的别名，在打开时仍使用数据库会话 ID。只读取用户和助手可见文本，忽略工具、思考、内部 meta/compact 记录；按 parentId/logicalParentId 与编辑重发墓碑投影当前分支，撤下已被替换的消息。普通助手追加按 cursor 增量读取，用户新分支或墓碑触发该日志重新投影。完整行指纹识别追加和重写，残缺替换或解析失败保留已提交正文，归档仍先于正文处理生效。源日志删除后撤下正文，数据库仍在的会话保留标题搜索。

不收录仅存在于云端的会话，云端行的删除标记规则不同，不能套用本地 NULL 判断；未保存到本机的正文也无法搜索。当前默认只使用共享配置目录中的 projects，不猜测注入的其他运行时目录。来源不兼容时不迁移或修改 WorkBuddy 文件。

打开和复制继续会话命令使用安装包中确认的 `workbuddy://chat/<id>`，不执行 CLI 或发送提示。真实图标提取自已安装应用的 icon.icns。数据库和 WAL 额外使用系统 vnode 通知，覆盖 FSEvents 对持续打开 WAL 的合并延迟；文件关闭、重命名和 WAL 重建会重新挂接监听，不轮询正文。停用来源和退出均关闭文件描述符与通知。

## Agent 默认开关与安装检测

首次启动以及重新打开搜索面板、设置时，只读检查已安装应用；Claude Code、Codex 还检查 PATH、常见用户安装目录及 Node 版本管理器的可执行文件。不执行命令、不启动 Agent、不访问网络，不以遗留历史目录作为已安装依据；失效的应用注册和废纸篓中的应用不计为安装。

未设置来源开关时，已检测到的来源默认开启，未检测到的默认关闭。检测结果不写入偏好，因此之后安装/移除应用仍可重新计算；用户手动开启或关闭（包括在已经自动关闭时明确关闭）才写入偏好，并优先于自动检测。允许用户手动启用未自动识别的安装，或使用保留在本机的历史数据。

全部来源关闭时，话题分类隐藏，不创建话题索引、监听或同步定时器，也不产生缺失 Agent 的同步错误。安装状态变化导致的来源关闭沿用原生命周期取消与结果撤下逻辑，缓存保留，旧动作失效。主开关和其他来源的手动设置不受检测影响。合成测试通过注入安装检测隔离本机环境，覆盖未安装无后台工作、自动随安装变化、手动覆盖持久化、缓存和旧动作撤回，以及桌面/CLI 安装检测。


DeepSeek Harness 支持已移除：设置、索引读取、打开动作、图标和官网均仅保留 Claude Code、Codex 与 WorkBuddy。兼容旧索引时先在只读查询中排除历史 Harness 行，随后由正常写入连接清理；不修改原始 Agent 数据。
